# References for the de-slop pass

Principles only. Nothing here was copied: no layout, text, image, or asset from these sites is used in this archive. The aim is to borrow editorial habits, not visual skin.

## Method

Web search was attempted first. The configured search integration returned HTTP 402, and DuckDuckGo served a bot challenge; Bing returned poor results for the queries. The references below were then opened directly and checked as live pages on 24 November 2026. Wikipedia and arXiv were used where a search result was needed to find the underlying source.

## Design and editorial references

| Source | What was taken | Why it fits |
|---|---|---|
| [The Public Domain Review](https://publicdomainreview.org/) | Image-first presentation. An object or frame is allowed to carry a page; captions state what the thing is and where it came from before any interpretation. | This archive has the same material problem: licensed photographs and a finite set of releases. The answer is better labelling, not more decoration. |
| [The Pudding](https://pudding.cool/) | One signature interaction per story. Motion is tied to the thing being explained and the rest of the page stays still. | Gives a concrete rule for the "motion only when it explains something" requirement without stripping every hover state. |
| [Bandcamp Daily](https://daily.bandcamp.com/) | The daily album-item shape: artist, title, label, date, a named writer, then the argument. Short entries stay factual. | A useful model for discography pages: the record's metadata leads, the prose follows, and no card needs a badge. |
| [Pitchfork — Albums](https://pitchfork.com/reviews/albums/) | Bylines, genre, release date, and a score attached to a named critic. Evaluation is attributed, never anonymous. | Fixes the current "many critics treat as her best" problem: either name the publication and year, or cut the claim. |
| [The Paris Review — The Daily](https://www.theparisreview.org/blog/) | Human rhythm: long sentences next to short ones; specific scenes instead of thesis statements; image credits placed with the image. | Direct antidote to evenly sized paragraphs and grand closing lines. |
| [Typewolf](https://www.typewolf.com/) | Restrained type pairing and clear hierarchy. Lists exist to identify fonts, not to decorate the page. | The archive keeps Cormorant Garamond and Inter; they need consistent scale, tabular figures, and 60–75 character lines more than new ornaments. |
| [Awwwards — editorial type](https://www.awwwards.com/websites/editorial/) | Editorial typography used as structure: masthead, column, rule, caption. | Studied as a category, not as a layout to copy. Confirms that strong editorial sites do not need a hero-card carousel on every route. |
| [MusicBrainz](https://musicbrainz.org/) | Release groups, dates, labels, and open data with visible provenance. | Used to cross-check date-sensitive discography facts. It is a finding aid with citations, not a substitute for a primary announcement. |

## "AI slop" references and the resulting checklist

| Source | What was taken | Why it fits |
|---|---|---|
| [Wikipedia — AI slop](https://en.wikipedia.org/wiki/AI_slop) | Definition: low-effort, mass-produced digital filler; "digital clutter" and "filler content prioritising speed and quantity over substance". | Names the failure mode without needing to accuse a person or a tool. |
| [Simon Willison — "Slop is the new name for unwanted AI-generated content"](https://simonwillison.net/2024/May/8/slop/) | "I attach my name and stake my credibility on the things that I publish." Unreviewed generated content is treated as discourteous to the reader. | Turns the fix into an editorial standard: every line must be something a keeper can stand behind. |
| [Why Slop Matters (arXiv:2601.06060)](https://arxiv.org/abs/2601.06060) | Three family traits: superficial competence, asymmetric effort, mass producibility. | Gives the audit its three tests: does the sentence carry information, did it need real work, and could it be pasted onto any other page? |

Checklist applied to this archive:

1. Delete "not X, but Y" framing and negation-led section titles.
2. Delete technical self-congratulation ("every route is a real page", "generated from one JSON file").
3. Attribute every evaluative claim, or remove it.
4. Delete decorative numbers, badges, and uppercase micro-labels that do not help navigation.
5. Replace repeated disclaimers with one plain statement in one place.
6. Break the repeated hero + three cards + numbered list rhythm; let content decide layout.
7. Make each caption a small record: date, place, maker, one context sentence.
8. Replace empty intensifiers (iconic, timeless, immersive, curated, tapestry) with a date, a name, or a number that can be checked.
9. Vary sentence length; remove grand closing lines.
10. Keep motion only where it clarifies state or direction; one signature interaction, not a global fade on everything.
